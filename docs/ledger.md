# 可追溯台账

> AI 建模最大的信任问题不是"算错"，而是**分不清哪句是真的**。
> 台账把"可信度"变成可查询的字段。

## 一条台账长什么样

```jsonc
{
  "id": "C-017",
  "claim": "环覆盖证书在 (ρ=980, n=8) 下成立，最大未覆盖距离 970.03 m",   // 数字来自 metrics.json
  "status": "verified",              // new | verifying | verified | refuted | stale
  "method": "解析不等式 + 网格枚举（0.1° 细扫）",
  "protocols": ["P1", "P3"],         // 跑过哪些验证协议
  "caliber": {
    "定义": "d_max = 环上相邻站角平分线处的最坏距离",
    "适用边界": "R=1800, r_min=1000；ρ>r_min 时不成立",
    "可外推": false
  },
  "evidence": ["out/metrics.json", "report.md"],
  "recompute": "python solve.py",    // P7：一条命令重算
  "depends_on": ["C-005", "C-007"],  // 上游一变，本条自动 stale
  "verified_at": "2026-09-12T12:10:00+08:00",
  "notes": "若 ρ>r_min，圆心成为盲区，覆盖率降至 88.7%"
}
```

## 状态机

```
                ┌──────────── 上游改动 ────────────┐
                ▼                                  │
  new ──▶ verifying ──▶ verified ──▶ stale ─────────┘
                  └──▶ refuted（留痕，不删）
```

| 状态 | 含义 | 能否被交付物引用 |
|---|---|---|
| `new` | 刚提出，还没验 | ❌ |
| `verifying` | 验证中 | ❌ |
| `verified` | 通过协议、有证据、有重算命令 | ✅ |
| `refuted` | **已被证伪**，连同证据保留 | ❌（但是资产，供后来人查） |
| `stale` | 上游参数/结论变过，本条作废待重验 | ❌ |

**`stale` 传播**：`invalidate("C-001")` 会把 C-001 及其**全部下游依赖链**一起置为 stale。
这是台账最实用的一个功能——改一个参数，机器告诉你哪些结论已经过期，
而不是靠人回忆"这条结论是不是也受那个参数影响"。

## 对账规则（`tsolve ledger check`）

一条 `verified` 的台账必须齐备以下四项，缺一即报错：

1. **证据文件**（`evidence` 非空且文件真实存在）；
2. **重算命令**（`recompute` 非空）——没有重算命令的结论等于口说无凭；
3. **口径定义**（`caliber.定义` 非空）——同一个数字换个口径可能是另一个意思；
4. **依赖清楚**（`depends_on` 指向真实存在且未被证伪/作废的条目）。

另外：`refuted` 条目本身**不报错**。它是留痕，不是错误。

## 数字零手写（P7 怎么落到代码里）

台账里的 `claim` 文本、报告模板、证伪记录模板里，**不许出现手写的数字**，
只能写 `{{m.路径}}` 或 `{{m.路径|格式}}`：

```markdown
建议每周备货 {{m.result.recommend_Q}} 件，相对基线多 {{m.result.gain_vs_baseline_per_week|.2f}} 元/周。
```

- `tsolve solve` 渲染时从 `out/metrics.json` 取值；**取不到值 → 构建失败**（不是留空、不是猜）；
- 数量级格式交给 Python 格式化（`.2f`、`.1%`、`,.0f`）；
- 成品里若还剩未解析的占位符，`tsolve audit` 会拦下来。

顺带一条踩坑：**JSON 键名不要含点号**（`profit_band_0.1pct` 这种会把占位符路径切断），
写成 `profit_band_0p1pct`。这不是洁癖——它会在渲染期直接报"取不到值"。

## 为什么 `audit` 要在临时目录重跑

同一目录重跑会带来一个隐蔽的作弊面：脚本上一步的产物还在原地，
"重跑"可能只是读了上次的结果。复制到临时目录、删掉 `out/` 再跑，
才是真正的"从原始数据重算一遍"。
