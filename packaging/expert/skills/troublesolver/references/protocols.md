# 七条验证协议 + 结论类型→必跑矩阵

> 协议不是写在提示词里给人看的文字，而是**能跑的检查器**（`scripts/troublesolver/checks.py`）。
> 引擎只认识**结论类型**，不认识你的领域 —— 这就是它能泛化的全部底气。

## 一、七条协议（每条的判据）

| # | 协议 | 判据 | 不通过怎么办 |
|---|---|---|---|
| **P1** | 双路径交叉 | 同一结论用两种**独立**方法（解析式 / 数值搜索 / 仿真）实现，**相对误差 < 1e-9** | 查哪一路写错；两路都留进台账 |
| **P2** | 对抗式最坏点审计 | 凡"恒成立 / 一定 / 总是 / 从无例外"：**粗网格**与**对抗搜索**必须同结论；两者不一致 → 判为**窄带陷阱**，以对抗搜索为准 | 结论降级为"在该分辨率下成立"，并如实报出搜索分辨率 |
| **P3** | 连续复核 | 离散网格算出的极值，必须用连续/自适应搜索复核；**报区间不报单点** | 报区间 + 说明窄峰宽度 |
| **P4** | 极限与量纲 | 参数 → 0/∞/临界值时退化为已知结果；量纲自洽 | 公式错，回上一步 |
| **P5** | 反例搜索 → 翻转边界 | 不只"找到一个反例"就收工，要给出**翻转边界**（哪个参数、翻转点在哪）；没找到就如实报"在该范围内未找到" | 把翻转条件写进"失效边界"章节 |
| **P6** | 口径声明 | 每个数字标：来源 / 定义 / 适用边界 / 能否外推；**不同口径的数字不得相减** | 补口径；有分歧的**两套都算、并列报出** |
| **P7** | 台账对账 | 对外每个数字都能由一条命令从原始数据重算；**禁止手抄** | 删掉手写数字，改为读 `out/metrics.json` |

**P2 / P3 / P5 是"主动找自己错"**，与只查格式的传统 QA 不是一回事 —— 这三条是门槛。

## 二、结论类型 → 必跑协议（引擎强制）

每条台账结论声明 `kind`（结论类型）。**标了 `verified` 的结论，如果它这一类该跑的协议没跑齐，`tsolve solve` 直接报错**，不许自称已验证。

| kind | 必跑 | 它防的是什么 |
|---|---|---|
| `等式` | P1 | 单条推导写错 → 双路径交叉 |
| `恒等式` | P1 + P4 | 边界情形不成立 → 极限检验 |
| `极值` | P1 + P3 | 极值在窄峰上，网格取不到 → 连续复核报区间 |
| `最优性` | P1 + P3 + P5 | 局部最优冒充全局最优 → 反例搜索 |
| `全称断言` | P2 + P5 | **粗采样整段跳过窄违例带** → 对抗搜索 + 翻转边界 |
| `覆盖` | P2 + P3 + P5 | 同上，且最坏点常落在边界上 |
| `存在性` | P5 | 只在特定区域存在 → 边界搜索 |
| `唯一性` | P4 + P5 | 退化情形下多重解 → 极限 + 边界 |
| `极限` | P4 | 收敛了，但不退化到已知结果 |
| `单调性` / `单调` | P1 + P5 | 区间内反向而没人知道 → 边界搜索 |
| `稳健性` | P5 | 扰动下结论翻转而没人知道 |
| `统计量` | P6 | 口径混用（数字可复算由 P7 兜底） |
| `预测` | P5 + P6 | 样本外失效 + 口径外推 |
| `口径相关` | P6 | 不同口径的数字被直接相减 |

**例外**：`status: "refuted"` 的条目**不需要 `kind`、不强制跑齐协议** —— 它靠"检查不通过"来立论。
检查失败还会把 `status == "verified"` 的条目**强制降级为 `refuted`** 并把反例写进 `notes`。

## 三、窄带陷阱（P2 的主角）

**症状**：用 3° 步长扫描，整段跳过**宽仅 2°** 的违例带，输出"恒成立"的假结论。
**对策**：把违例带中心放在**两个网格点正中间**时最容易复现；判据是
`grid_argmax ≤ 0 < adversarial_argmax` → 引擎自动标记 `flipped = True` 并写明"网格给出的是假结论"。

**诚实的边界**：有限预算的对抗搜索**无法保证**找到任意窄的特征 ——
无坡度的孤立尖峰只能靠扫描分辨率。所以 P2 每次都把**搜索分辨率一起报出来**，
把"未找到"读作"**在该分辨率下未找到**"，绝不写成"已证明成立"。
