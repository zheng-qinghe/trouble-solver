# 阶段 1-2：基线与建模

> 前置条件：`charter.md` 已通过 `tsolve charter check` 且用户已在卡点① 确认口径。
> 本阶段产出**代码**，不是散文：**数字只能从脚本里出来**（P7）。

## 一、铁律

1. **基线先行，且基线必须可复现**（卡点②）。基线是"最笨但可信"的做法——
   历史均值、现行规则、人工经验值，随便哪个都行，但**必须能被一条命令重算**。
   没有基线就没有"改善了多少"，报告里的增益全是空的。
2. **解析优先，数值兜底**：能写闭式解就写闭式解；写不出就数值搜索。
   **两条路都要写**（P1 的物理前提）——只写一条，就没有交叉验证。
3. **数字只从 `out/metrics.json` 出**。脚本之外任何地方（包括报告、台账、
   口头结论）**禁止手写数字**，只能引用 JSON 里的键。
4. **允许多个口径并列**：口径有分歧时不要挑一个"对的"藏着分歧，**两套都算、并列报出**（P6）。
5. **不追求"最优"这个词**：写"在 X 口径、Y 假设下的最优解"，并准备好它的失效边界。

## 二、要产出的东西

| 产物 | 说明 |
|---|---|
| `solve.py` | 求解脚本，唯一出口 `out/metrics.json`；末尾需把关键数字**打印**出来（人肉可核对） |
| `out/metrics.json` | 所有对外数字的结构化出口，键名**不得含点号**（点号会切断报告占位符路径） |
| `ledger.spec.json` | 结论清单（声明式）：每条 claim 用 `{{m.路径}}` 引用 JSON 里的真实数字 |
| `report.template.md` | 报告模板：正文中的每个数字都写成 `{{m.路径|格式}}` 占位符 |
| `falsify.template.md` | 证伪记录模板，由阶段 3 填写 |

## 三、建模步骤（按顺序，可跳步但要留痕）

1. **写基线**：现做法直接实现一遍，算出现状指标。
2. **写路径 A（解析）**：把 charter 里的目标与约束写成公式，能闭式就闭式。
3. **写路径 B（数值）**：**独立实现**同一目标（枚举／搜索／仿真），不要复用 A 的中间量。
4. **对账 A 与 B**：相对误差 < 1e-9 才继续；不一致时先怀疑取整与边界，而不是"差不多就行"。
5. **落台账**：给每条结论起 `C-00x`，写清 method / protocols / caliber / evidence / recompute。
6. **标注口径**：每个数字的来源、定义、适用边界、能否外推。**不能外推的必须写 `可外推: false`**。

## 四、完成标准（可机器校验）

- `tsolve solve <case_dir>` 通过：说明卡点①、卡点②、台账对账、占位符注入全部过关；
- `out/metrics.json` 里所有对外的数字都有键（报告里没有裸数字）；
- 参考文献/结论里出现的每个数都能在 `metrics.json` 里找到同名键。

## 五、反模式（出现即打回）

| 反模式 | 为什么错 |
|---|---|
| 先写报告再补代码 | 数字一定是"编"出来的，P7 直接就废了 |
| 报告里写"约 133 件" | "约"字说明它不是算出来的——去把键补进 JSON |
| 两条路径共用同一个函数 | 不叫交叉验证，叫复制粘贴（P1 要求实现独立） |
| 只报一个口径 | 口径分歧被藏起来，交付物看起来很干净但不可用 |
| 给一堆用不上的指标 | 每个数字都要有人为它负责；不做没用的数 |
